Differences from the source that are not literal:

- Refusals: the source listened for every browser response, in any frame, across navigations. e2e has no response listener and `route.continue` hides the response, so `observeResponses` (in `e2e/flows/support/courtai.ts`) registers a catch-all `browser.route('**/*')` that plays the network for same-origin non-`/api` requests: it fetches the request from the test process, records the status in a test-scoped list (so it survives navigations), and fulfills the browser with the same status, headers and body (binary bodies via a file under `.e2e/proxy/`). `browser.route` sees sub-frame requests, so nested frames and frame images are covered. `/api` requests `fallback()` to the contract, whose fulfilled status is recorded in `api.requests[].status`. An earlier in-page observer (fetch/XHR wrapper plus Resource Timing) was dropped after review: it missed frame responses, was reset by each navigation, and threw on relative XHRs in `about:srcdoc` frames. Not covered: cross-origin requests (CSP blocks them in the bridge) and WebSocket traffic.
- Fixture: `waitlistedTest` in `e2e/flows/support/courtai.ts` installs the contract with `{ waitlisted: true }`; `api.override` keeps that option.
- No agent steps. The source's `browserHealth` fixture (uncaught page errors) is the `api` fixture's page-error check.

Coverage lost by retiring the Playwright spec: the browser receives a proxied copy of each same-origin non-`/api` response rather than the network's own, so a defect that only shows through the original transport (compression, caching headers, streaming) would not be seen by this test; none is known to matter for this page. Cross-origin and WebSocket responses are not observed.

## Gaps

- `permissions` (clipboard), `clock`, `toHaveCSS`, `click({ clickCount })`, `page.on('console'|'pageerror')` and `locator.evaluate` are `missing` in the Playwright guide. Workarounds are in "connect" above. `page.on('request')` is not listed as missing: `browser.route` observes requests, including the sandboxed card frame's.
- `toHaveScreenshot` is supported (`same`); only `fullPage`, `clip`, `animations`, `caret`, `scale` and `stylePath` are `missing`. `filter-panel-parity.spec.js` can be checked for those options before it is called `stays`; its Linux baselines are the other thing to settle.
- Real clipboard read: e2e cannot grant clipboard permission, so no test reads the real clipboard any more. The sink checks what the app writes, not that the browser accepts it. `docs/e2e-flows.md` says so.
- `page.on('response')` has no listener form, `browser.waitForResponse` needs an open page (`APP_NOT_OPEN` before `app.open`) and resolves once, and `route.continue` hides the response. Workaround in "waitlist": a catch-all route that proxies same-origin non-`/api` requests and records their statuses. A `route.fetch()` (Playwright) or a response event would remove the proxy; feedback not sent.
- `expect(...).toHaveCount(0)` passes at once when the node is absent, so a check that something never appears is only as strong as the wait before it.
- `e2e run --grep "other 403 responses"` selects tests by title (one check per target), so a mutation run can target one test. An earlier note here said there was no title filter; that was wrong.
- Two mutations escape both the old and the new suite, so they are inherited weaknesses, not regressions: `forbidden` 403 responses never settling in the axios handler, and an erroneous waitlisting delayed 700 ms after the 403. The checks look at the screen right after the double `requestAnimationFrame`, so a held or late reaction passes. Fixing either needs a check that waits a fixed time with the banner absent (a negated `toBeVisible` can pass at once when the node never appeared, so it does not hold absence); optional.
- No `npx e2e feedback` was sent this session.
