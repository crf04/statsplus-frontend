Differences from the source that are not literal:

- Clock: `page.clock` is `missing`. `freezeClock` in `flows/support/courtai.ts` replaces `Date` with a Proxy before the app runs and also pins the implicit now of `Intl.DateTimeFormat#format()` and `#formatToParts()` (review finding: Playwright's fixed clock freezes those too, and a `.format()` call with no date reached the real date). `performance.now` and timers are not frozen, as with `setFixedTime`. `Date.prototype.toLocale*String` act on a date, so they need no patch.
- Timezone: the source set none, so it ran in the machine's zone (America/New_York here, presumably UTC on the CI runner). The `desktop` and `phone` targets are Asia/Tokyo, east of UTC, so a UTC-midnight date formatted in the viewer's zone looked right on both. A third target, `desktop-west` (1440x900, America/New_York), was added in `e2e.config.ts`. Every flow runs on it (`test:flows` passed 276/276 on three targets); the older flows are unchanged. Mutation 64 (the date heading formatted in the viewer's zone) fails the port only on `desktop-west`.
- Screenshots: `app.screenshot` captures the viewport, not `fullPage` (the source screenshots were artifacts, never compared). The full-page artifacts are lost for the nine ported tests.
- Request observation: none in the nine ported tests.
- Targets: the source ran `chromium` (Desktop Chrome, machine timezone); e2e runs desktop 1440x900 and phone 390x844 (Asia/Tokyo) and desktop-west 1440x900 (America/New_York).
- `getByLabel('9 targetable players, ...')` matches an `aria-label` substring, so it uses `{ exact: false }`.

## Gaps

- `permissions` (clipboard), `clock`, `toHaveCSS`, `click({ clickCount })`, `page.on('console'|'pageerror')` and `locator.evaluate` are `missing` in the Playwright guide. Workarounds are in "connect" above. `page.on('request')` is not listed as missing: `browser.route` observes requests, including the sandboxed card frame's.
- `toHaveScreenshot` is supported (`same`); only `fullPage`, `clip`, `animations`, `caret`, `scale` and `stylePath` are `missing`. `filter-panel-parity.spec.js` can be checked for those options before it is called `stays`; its Linux baselines are the other thing to settle.
- Real clipboard read: e2e cannot grant clipboard permission, so no test reads the real clipboard any more. The sink checks what the app writes, not that the browser accepts it. `docs/e2e-flows.md` says so.
- `page.on('response')` has no listener form, `browser.waitForResponse` needs an open page (`APP_NOT_OPEN` before `app.open`) and resolves once, and `route.continue` hides the response. A proxy route can record statuses but missed or misreported these Codex mutations against the source: 307 to a non-API 403, 308 to a non-API 403, 307 to an API 403, a two-hop 307 to 308 to 403, a cross-origin 403 blocked by the bridge CSP (all passed the port, failed the source), and a detached iframe keepalive 403 (failed the port, passed the source). Tests that observe responses therefore stay in Playwright ("waitlist"). A response event or `route.fetch()` would change that; feedback not sent.
- Request observation: e2e has no `page.on('request'|'response'|'requestfailed')` and no `route.fetch()`. A `browser.route` sees the first request of a redirect but not the followed ones and never sees CSP-blocked attempts (the bridge sends `connect-src 'self'`; production sends none), and patching each hole opened another. Tests that count what the client sent or received stay in Playwright: `attribution` (send-once) and `waitlist` (the two refusal tests), with the mutation evidence cited in each section. The catch-all proxy `observeResponses` that shared these limits was removed with the waitlist revert, so nothing in the e2e flows still depends on it. Feedback drafted with `--dry-run`, not sent.
- `expect(...).toHaveCount(0)` passes at once when the node is absent, so a check that something never appears is only as strong as the wait before it.
- Two mutations escaped both suites on the full five-test port: `forbidden` 403 responses never settling in the axios handler, and an erroneous waitlisting delayed 700 ms. They concern the staying `other 403 responses` test, so they stay Playwright's weakness too.
- `e2e run --grep "other 403 responses"` selects tests by title (one check per target), so a mutation run can target one test. An earlier note here said there was no title filter; that was wrong.
- Clock: `page.clock` is `missing`; `freezeClock` (init script that proxies `Date` and pins `Intl.DateTimeFormat#format()`/`formatToParts()` with no date) is the workaround for tests that pin Today or relative ages ("slate" above). Full-page screenshots are not available (`app.screenshot` is the viewport).
- Timezone is per target (`web({ timezoneId })`), not per test, and a target runs every flow. The `desktop-west` target (America/New_York) was added for the slate date coverage; the `phone` and `desktop` targets stay in Tokyo.
- Request observation, redirect case: `api.sent` records only what reaches the `/api` contract. A slate request that arrives by an HTTP redirect to `/api/games/slate` passes a `page.on('request')` assertion and fails `api.sent`, so the slate navigation test stays in Playwright.
- No `npx e2e feedback` was sent this session.
